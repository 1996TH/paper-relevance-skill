# 논문–연구 분야 분류와 관련성 정리

## 작업 순서
1. 연구 읽기: references/research.md에서 연구 분야, 막힌 문제, 꼭 확인할 것을 읽는다.
   판단에 필요한 정보가 없으면 추정하지 말고 묻는다.
2. 논문 읽기: 본문과 부록(실험 설정)을 읽는다. 읽지 않은 부분은 기록해 둔다.
3. 분류: 논문의 기여를 기준으로 해당하는 분야를 고른다. 여러 개일 수 있고,
   없으면 '해당 없음'이다. 해당하지 않는 분야는 이유를 하나씩 적는다.
4. 관계 정리 (우선순위 순서):
   1. 막힌 문제와 논문이 어떻게 연결되는지
   2. 연구 도메인에 적용할 때 걸리는 점 (research.md의 '꼭 확인할 것' 포함)
   3. 다른 분야와의 접점
   근거로 절·표·그림·부록 번호를 붙인다. 연결점이 없으면 억지로 만들지 않는다.
5. 구현 확인: 공식 구현의 옵션이나 동작을 언급할 때는 소스를 직접 확인한다.
   확인하지 못했으면 "확인 필요"로 쓴다.
6. 검토: 인용 번호와 수치를 원문과 다시 대조한 뒤에 답한다.

## 출력 형식
- 맨 위에 한 줄 판단: 분야 · 관련도(높음/부분/낮음/보류) · 이유 · 읽은 범위
- 모든 진술에 [원문](논문·공식 구현) / [해석](내 판단) / [제안](해 볼 만한 방법)을 붙인다.
  블록 전체가 원문 요약이면 제목에만 한 번 표시한다.
- 마지막에는 [제안] 다음 할 일 하나만 둔다.
- 요청이 없으면 대화로만 답하고 파일을 만들지 않는다.

## 수정 요청을 받았을 때
- 전체를 다시 쓰지 않고, 바뀐 부분만 섹션 이름과 함께 보여 준다.
