# 실행 계약

## 목차

1. 입력 확보와 원문 준비
2. 내부 결과 형식
3. 상태와 근거 규칙
4. 검사와 보고서 생성
5. 실패 처리와 전달

## 1. 입력 확보와 원문 준비

먼저 SKILL.md의 계획을 보여 주고 사용자 확인을 받는다. 실행 기록에 제시한 계획, 실제 확인 응답, 적용 범위를 남긴다. 이미 확인받은 동일 계획은 반복 확인하지 않는다. 계획 확인 전에는 아래 원문 준비·분석 명령을 실행하지 않는다.

아래 명령은 일반 실행 환경의 예다. Claude Code 보호 훅을 연결한 프로젝트에서는 [guard.md](guard.md)의 실제 경로와 제한된 실행 형식을 사용한다. 그 모드에서는 셸 변수 확장과 프로젝트 밖 입력이 허용되지 않는다.

사용자의 PDF·URL·제목과 자연어 연구 맥락을 받아 아래 파일을 **에이전트가** 만든다. 사용자는 JSON이나 원문 텍스트를 준비할 필요가 없다.

첨부 파일을 우선 사용한다. 링크나 제목이면 제공된 탐색 도구로 정확한 논문·버전을 확인하고 공식 또는 저자가 공개한 원문을 확보한다. 저자·연도·버전을 확인하지 못했으면 미확인으로 남긴다. 원문을 읽지 못했는데 제목이나 초록으로 본문 내용을 보충하지 않는다. 접근 권한을 우회하지 않는다.

각 실행마다 새 폴더를 선택한다. 아래 `paper_skill_dir`에는 실행 중인 스킬의 절대 경로를 지정하고, 예시 입력·출력 경로를 실제 경로로 바꾼다.

```bash
python3 "$paper_skill_dir/scripts/prepare_source.py" /path/paper.pdf --output /path/run/source.json --origin https://official.example/paper --scope full_text
```

- 입력은 로컬 PDF 또는 UTF-8 텍스트/Markdown이다. 스크립트가 URL을 다운로드하지 않는다.
- PDF는 `pypdf`가 필요하다. 없으면 이미 사용 가능한 PDF 추출 도구로 만든 UTF-8 텍스트 사본을 사용할 수 있다. 추출 경로·원문 출처·확보 범위를 기록하고 원본을 보존한다. 이 경우 검사되는 해시는 텍스트 사본의 해시이며, 텍스트 페이지/행을 원본 PDF 쪽수라고 표시하지 않는다. 의존성을 자동 설치하거나 전역 설정을 바꾸지 않는다.
- Python·로컬 파일·웹 도구가 없는 환경에서는 가능한 자료 읽기와 대화 분석까지만 진행하고 자동 검사 미실행을 표시한다. 코드 실행이나 `complete` 상태를 꾸미지 않으며, 원문 접근까지 불가하면 그 한계와 필요한 입력을 알린다.
- `--scope`는 확보한 자료의 범위로 `full_text`, `excerpt`, `abstract_only` 중 하나다. 초록이나 일부 발췌를 텍스트 파일로 저장했다면 그에 맞는 범위를 지정한다.
- 최대 입력 크기는 50 MiB, 최대 PDF 페이지 수는 500이다. 초과·암호화·빈 텍스트·추출 실패는 명시적 오류다. 자동 OCR은 하지 않는다.
- PDF 쪽수는 **실제 PDF의 1부터 시작하는 페이지 번호**다. 인쇄된 쪽수와 구분한다. 텍스트 입력은 하나의 문서 페이지로 취급한다.
- 출력은 새 파일에만 쓴다. 기존 출력이 있으면 덮어쓰지 말고 새 이름을 고른다.

`source.json`은 다음 구조를 가진다. 원문 경로는 이 JSON의 부모 폴더를 기준으로 해석한다.

```json
{
  "schema_version": 1,
  "source": {
    "file": "../paper.pdf",
    "sha256": "원자료 바이트의 SHA-256",
    "origin": null,
    "media_type": "application/pdf",
    "available_scope": "full_text",
    "extractor": "실제 추출기 이름과 버전",
    "page_count": 2
  },
  "pages": [
    {"page": 1, "text": "첫 페이지 텍스트"},
    {"page": 2, "text": "둘째 페이지 텍스트"}
  ],
  "warnings": []
}
```

페이지별 `text.splitlines()`의 1부터 시작하는 행 번호를 근거 위치로 사용한다. 텍스트 추출과 원문 읽기를 구분한다. 텍스트를 읽고 필요한 그림·표·수식은 실제 PDF 페이지와 대조한다. `warnings`에 빈 페이지가 있으면 전체 분석 완료를 주장하지 않는다.

## 2. 내부 결과 형식

아래는 필드 설명용 형식이다. 실행 결과에는 실제로 확인한 값만 넣는다. 서지정보를 확인하지 못했으면 `null`, 알려진 저자가 없으면 빈 목록을 사용한다.

```json
{
  "schema_version": 1,
  "status": "complete",
  "paper": {
    "title": null,
    "authors": [],
    "year": null,
    "identifier": null
  },
  "source_packet_sha256": "source.json 파일 바이트의 SHA-256",
  "reading": {
    "scope": "full_text",
    "pages_read": [1, 2],
    "visual_pages": []
  },
  "research_context": "이번 요청에서 제공한 연구 조건 또는 null",
  "relevance": {
    "level": "부분",
    "reason": "연구 질문·방법·평가와의 연결을 해석한 이유"
  },
  "summary": {
    "problem": "원문에서 확인한 문제",
    "method": "저자가 바꾼 것과 작동 원리"
  },
  "claims": [
    {
      "id": "C1",
      "statement": "원문 근거가 있는 핵심 주장",
      "evidence": [
        {"page": 1, "start_line": 1, "end_line": 2, "quote": "해당 행 범위에서 발췌한 짧은 근거"}
      ],
      "conditions": "데이터·비교 대상·지표·제약 등 성립 조건"
    }
  ],
  "connections": [
    {
      "idea": "현재 연구에 적용해 볼 제안",
      "difference": "원문과 연구 조건의 차이",
      "test": {
        "baseline": "확인된 비교 대상 또는 미정인 부분",
        "metric": "확인할 지표 또는 결정이 필요한 지표",
        "failure_condition": "제안이 유효하지 않다고 판단할 조건"
      }
    }
  ],
  "limitations": ["읽은 범위·분석·적용의 한계"],
  "next_action": "다음 행동 하나",
  "semantic_review": {
    "mode": "self",
    "checked_claim_ids": ["C1"],
    "notes": "실제로 수행한 주장과 근거의 의미 대조 범위"
  }
}
```

`connections`는 제안이다. 사용자가 정하지 않은 수치 임계값·실험 설정을 확정 사실로 넣지 않는다. 연결이 없거나 연구 맥락이 없으면 빈 목록을 사용한다. `semantic_review.mode`는 `self`, `independent`, `not_performed` 중 실제 수행 상태다.

렌더러가 관련성 이유에 `[해석]`, 연결 항목에 `제안` 표기를 붙인다. 해당 필드에 같은 접두어를 반복하지 않는다. `next_action`은 구체적인 다음 행동 1~2문장으로 쓰고 긴 실험 조건은 `connections`에 배치한다.

## 3. 상태와 근거 규칙

| 상태 | 요구 조건 | 의미 |
|---|---|---|
| `complete` | 전체 텍스트 범위, 모든 확보 페이지 읽음, 빈 추출 페이지 없음, 연구 맥락 있음, 모든 주장 의미 검토 | 요청 범위의 분석과 검사 완료. 논문 자체의 진실성을 보장하는 상태가 아님 |
| `partial` | 읽을 수 있는 근거는 있으나 일부 본문·초록만 읽었거나 연구 맥락·검토가 부족 | 확인한 범위 안에서 전달하는 유효한 부분 결과 |
| `blocked` | 의미 있는 원문을 읽을 수 없음 | 원문 확보나 추출 문제로 분석 불가; 필요한 다음 행동 보고 |

- `complete`와 `partial`에는 근거가 있는 주장을 1~5개 둔다. 근거 하나도 없으면 `blocked`로 처리한다.
- 주장 ID는 유일해야 한다. 각 근거의 페이지는 `pages_read`에 포함되어야 한다.
- 근거의 시작·끝 행을 확인한다. 인용은 최대 1,200자이며 공백·줄바꿈을 정규화한 뒤 해당 행 범위 안에 있어야 한다. 한 행에 억지로 맞추지 않는다.
- `source_packet_sha256`은 원자료 해시와 다르다. `prepare_source.py`가 준비된 `source.json`의 실제 바이트를 해싱해 출력한 `SOURCE_PACKET_SHA256` 값을 넣는다. 보호 모드에서도 별도의 해시 계산 명령은 필요 없다. 검사기는 원자료와 원문 묶음의 변경을 각각 확인하고, 같은 추출기로 원자료를 다시 추출해 페이지 텍스트도 대조한다. 추출기 버전이나 결과가 달라졌으면 새 실행 폴더에서 원문 묶음부터 다시 준비한다.
- `reading.scope`에는 실제 읽은 범위를 쓴다. 초록·발췌로 준비한 자료를 `full_text`라고 올릴 수 없다. 추출되었다는 이유만으로 `pages_read`를 채우지 않는다.
- 연구 맥락이 없으면 `research_context: null`, 관련도 `보류`, `connections: []`로 두고 `partial`을 사용한다. 가장 필요한 연구 질문 하나를 `next_action`에 적는다.
- `blocked`는 `source_packet_sha256: null`, `reading.scope: "unavailable"`, 빈 읽기·시각 확인 페이지, 빈 주장·연결 목록, 관련도 `보류`를 사용한다. `summary`의 문자열은 비워도 된다. 불가 이유는 `limitations`와 다음 행동에 적는다.
- 형식상 통과해도 인용이 주장과 의미상 연결되지 않을 수 있다. 조건·반례·수치의 맥락은 별도 대조한다.

## 4. 검사와 보고서 생성

```bash
python3 "$paper_skill_dir/scripts/check_result.py" --result /path/run/review.json --source /path/run/source.json
python3 "$paper_skill_dir/scripts/render_report.py" --result /path/run/review.json --source /path/run/source.json --output /path/run/report.md
```

`blocked` 결과는 두 명령에서 `--source`를 생략한다. 렌더러는 같은 검증 함수를 사용하며 결과 JSON에서 보고서를 만든다. 원문 인용은 내부 검사에 사용하고 보고서에는 요약한 주장·페이지/행 근거를 출력한다. 인용·출처 이용 제한을 지킨다.

| 종료 코드 | 처리 |
|---|---|
| `0` | 완전 상태의 형식·근거 위치 검사 통과. 보고서 전달 가능 |
| `3` | 유효한 `partial` 또는 `blocked` 결과. 제한 사항과 함께 전달 가능 |
| `1` | 결과 결함. 오류를 수정한 뒤 다시 검사 |
| `2` | 입력·원문·설정 오류. 자료나 실행 조건을 확인 |

검사 명령·출력·종료 코드를 실행 폴더에 남긴다. `1`·`2`에서는 보고서를 만들지 않는다. `0`·`3`에서 생성되는 보고서는 새 파일이어야 한다. 생성 후 내용 변경은 JSON에서 하고 새 출력명으로 다시 검사·렌더링한다.

## 5. 실패 처리와 전달

두 번까지 자동 수정한 뒤 같은 문제가 남으면 중단한다. 누락된 사실을 만들어 넣거나 검사 규칙을 느슨하게 바꾸지 않는다. 원본 접근·도구 제약은 실제 수행 상태로 기록한다.

사용자에게는 보고서의 다섯 항목, 실제 읽은 범위, 미확인 사항과 다음 행동을 전달한다. 중간 JSON 준비를 사용자 과제로 넘기지 않는다. 파일을 전달할 때는 현재 환경의 저장·첨부 절차를 따른다. 스크립트 실행 성공만으로 분석이 옳다거나 훅·운영체제 보호가 활성화됐다고 설명하지 않는다.
